# Packaging

Every release auto-generates ready-to-submit package-manager files from the
release assets (the same URL and SHA-256 that `tools\Pack-Release.ps1` produced).
They are regenerated by `tools\Release.ps1` and committed, so this folder always
matches the latest tag.

```
packaging/
  winget/<PackageId>/<version>/<PackageId>.yaml               # version manifest
  winget/<PackageId>/<version>/<PackageId>.installer.yaml     # installer
  winget/<PackageId>/<version>/<PackageId>.locale.en-US.yaml  # default locale
  scoop/scottimizer.json                                      # Scoop bucket manifest
  chocolatey/scottimizer.nuspec                               # Chocolatey package
  chocolatey/tools/chocolateyinstall.ps1                      #   install script
  chocolatey/tools/chocolateyuninstall.ps1                    #   uninstall script
```

Regenerate by hand for a version:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\New-PackageManifests.ps1 -Version 2.1.2
```

The SHA-256 is taken from `-Sha256`, then `dist\Scottimizer-Advanced.zip.sha256`,
then the published release asset — so it works before *or* after the release exists.

Submit everything with one command:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\Submit-Packages.ps1 -Target all
```

`-Target` is one of `winget`, `scoop`, `choco` or `all`. Add `-DryRun` to print
the commands without running them.

## winget

Validate locally (winget's own checker):

```powershell
winget validate --manifest packaging\winget\SCOTTYinCntrl.Scottimizer\2.1.2
```

Submit with Microsoft's `wingetcreate`:

```powershell
winget install --id Microsoft.WingetCreate -e
wingetcreate submit packaging\winget\SCOTTYinCntrl.Scottimizer\2.1.2\SCOTTYinCntrl.Scottimizer.yaml
```

This opens a PR against [microsoft/winget-pkgs](https://github.com/microsoft/winget-pkgs).
A reviewer merges it, and then `winget install SCOTTYinCntrl.Scottimizer` works for
everyone. (`tools\Submit-Packages.ps1 -Target winget` does exactly this.)

Notes:
- The zip ships `Scottimizer.exe` at the archive root, so the nested installer path
  is `Scottimizer.exe` with the `scottimizer` command alias.
- There was an earlier PR for **2.1.0** ([#453051](https://github.com/microsoft/winget-pkgs/pull/453051)).
  If it is still open when you submit a newer version, either wait for it to merge
  or add the new version's files to that same PR branch instead of opening a second one.

## Scoop

The manifest is a standard bucket entry with `checkver`/`autoupdate` pointing at
GitHub Releases, so Scoop keeps it current automatically.

Fastest route — your own bucket (fully automated by the script):

```powershell
# first time only: create the bucket repo
powershell -NoProfile -File tools\Submit-Packages.ps1 -Target scoop -CreateBucket
# then users install with:
#   scoop bucket add scottimizer https://github.com/SCOTTYinCntrl/scoop-bucket
#   scoop install scottimizer/scottimizer
```

Wider reach — the official `Extras` bucket:

1. Fork [ScoopInstaller/Extras](https://github.com/ScoopInstaller/Extras).
2. Add `packaging\scoop\scottimizer.json` as `bucket\scottimizer.json`.
3. Open a pull request. The `Excavator` bot updates the hash on future releases
   because `autoupdate` is configured.

## Chocolatey

Requires the [Chocolatey CLI](https://chocolatey.org/install) and a community
account. Build and push:

```powershell
choco pack packaging\chocolatey\scottimizer.nuspec --outputdirectory packaging\chocolatey
choco push packaging\chocolatey\scottimizer.2.1.2.nupkg --source https://push.chocolatey.org/ --api-key <your-key>
```

Get the key from <https://community.chocolatey.org/account>, or set
`$env:CHOCO_API_KEY` and run `tools\Submit-Packages.ps1 -Target choco`.
New packages go through moderation before they appear.
